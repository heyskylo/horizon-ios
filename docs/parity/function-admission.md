# Ordinary function command admission (H144)

The bounded defect is installation of a function with an invalid ordinary line. Java 26.3 parses every ordinary line at function compilation permission and rejects the entire file on a syntax error. Macros are expanded later; ordinary lines within a macro file still compile at admission.

The frozen source is `00f6358e7a7d4f168450fe6d74cbe82100dcc080`. A real format-121 pack supplies independent good/other functions, a valid/unknown/valid file, and a valid/owner-only/valid file. Both invalid files leave scores at -99 in Java, before and after reload. The untouched Game admits them and changes both scores to 2. Missing-function behavior is an independent control. This is command admission, not validation by execution.

The predeclared canonical program has **105 complete records**: exact messages/styles, callbacks, fresh result/success stores, score mutations, owner UUID/type/Health/mode/position, loaded chunk/floor and relative clock zero. All records remain strict. Absolute startup clocks and pack-list output are predeclared raw diagnostics. Pack admission is independently demonstrated by two valid functions. Metadata and function-tag dependency closure are outside this task.

The original program source SHA-256 is `518da905a78df4f44d308e8e1fb0e6848271591f70e6481e61bb7a415562693c`; emitted script SHA-256 is `ec105ec6558398195ea92d4d5ea844b229447987954baa4641a9ecd5d9ab2083`. ## Admission boundary

Game loads a candidate DataStore without exposing it. Explicit reload/pack-change paths refresh actual world tables first; the lazy initial load already has those tables. Admission clones existing command registries at `fns.command_level()`, refreshes their actual enchantment snapshot, and supplies candidate function/tag/predicate/modifier IDs. It parses only ordinary lines using the existing feature-aware dispatcher. An error removes the whole function and records its command text, error and cursor. After pruning, the final store is committed and exposed function IDs refresh. No candidate line executes during validation.

The old store remains active during synchronous world-table refresh; no candidate function is installed before validation. Existing pending-load/schedule handling, pack order, macro substitution, function execution, returns and tag dependency behavior are preserved. The independent custom-enchantment integrated-world loader gap is not repaired or claimed.

## Regression coverage and limits

The resource-backed actual Game regression creates a real pack and invokes functions through the command route. The old assertion fails because the bad function executes; the identical regression passes on the fixed source. Controls cover valid same-pack predicates at initial load and after adding a fresh predicate on reload, permission-2 rejection at both phases, no admission-time score mutation, deferred macro lines, ordinary-line rejection inside macro files, lexical slash rejection, continuation/sequence/return behavior, final exposed IDs and unchanged clock/owner permission. Existing H147 terminal-feedback and H154 fallthrough-return behavior are independent.

Raw Java load diagnostics, complete records, absolute clock traces, pack lists, rejected attempts, binaries, source diff and manifests are retained under `.local/h144/`. The executable original v1 and corrected v2 definitions are retained there. No claim covers all command grammar, metadata, function tags, custom-registry lifecycle, network delivery or scheduling parity.
