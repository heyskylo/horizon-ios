# Chorus-flower drops after actual projectile impacts

Accepted chorus-flower Arrow-kind/Snowball impacts now supply actual projectile presence to the direct block's loot. The private target-position context exists only inside the existing `with_level` call. Its callback matches that position; neighbor, default and machine drops keep no-entity behavior. The old destruction wrapper delegates with presence false. Owner/rule gates, pot/trident/dripstone and other projectile branches remain unchanged.

The Items engine already supports the empty `entity_properties`/`this` presence condition used by the vanilla chorus table. This does not add a full projectile predicate view or repair nonempty/custom-table semantics. The shared Arrow enum reaches tipped/spectral variants in source, but runtime proof is ordinary arrows and snowballs only. No natural-break lifecycle, trajectory, all-projectile or packet claim.

## RNG and source reach

The callback still selects its table's named stream first, or level RNG as fallback. Old `block_drops_with` delegates to `block_drops_full` then `block_drops_exploded` with `sequences=None`, `explosion=None`, presence false. New calls the same final adapter with the **already selected same random reference** and those same options, changing only matching-target presence. `None` does not reselect or erase a stream: the internal override requires both a table sequence and a supplied sequence pool. Tool, dynamic expansion, output/pop/pending/XP/event pipeline remain unchanged.

A controlled loader/callback unit loads the real gravel table through `Items::load`/`PackOverlay`, retaining or removing its sequence to exercise both actual callback branches. Output stacks, named stream words and four subsequent level-random longs match old/fixed exactly. Two fixture catalogs have test-process lifetime to meet the existing callback borrow; no production lifetime/API change. This is source/unit continuation evidence, not live custom-pack or Java distribution parity. The shared callback adapter reaches existing block drops, with presence false everywhere except the approved impact scope.

Original v1 Java did not step the frozen world; it is retained as rejected setup. V2 adds `/tick step 1` before each tick and keeps all impact/drop expectations. Rejected collection-field, unchanged-rule control and catalog-borrow compile attempts are retained separately. The qualified old/fixed pair uses V2 throughout. Scripts/references, all raw traces, bytecode, source audits, Game/unit binaries, hashes and real/unknown phase times remain protected in `.local/h116`.
