## Authoritative context and coverage

`Game::items()` selects the active world's catalog over resource defaults. Its `ItemInfo.max_stack` comes from the existing `item_defaults` loading/override route. The additive saved component/item APIs compare the actual item's positive Int patch with that loaded prototype. Unknown prototypes and known items with no stack-size component retain their patch; the existing component-key metadata prevents treating the effective64 fallback as a prototype. The existing context-free encoders and live `components_tag` stay unchanged; no decoder, model field, static table or effective-stack policy changes.

All four current production Game ItemEntity serialization callers use the same context-aware family writer: command NBT getter, persistence, Nether transfer and End transfer. Transfer call sites already have the active Items context, so no wider subsystem API is added. Runtime proof covers stationary ItemEntity command saved reads only; persistence/transfer context carry is source-reviewed, without reopen or dimension-lifecycle claims. Other families, including Player/equipment/container/template and nested-stack context-free writers, remain unchanged and unresolved for this default. This is not universal saved-stack closure.

Decoded-input and fresh/no-raw model units use actual `Items::catalog` input, builtin prototypes, a controlled custom prototype, unknown ID, nondefault, removal and unrelated custom_data. A second catalog load changes the same stone prototype64→7 and verifies that the new context, rather than a table or captured value, decides omission. They preserve exact live StackData, unsaved output and the old context-free encoder. Both identical final unit assertions fail at the old default patch before the comparison and pass after it. The old unit includes common additive API plumbing delegating to old behavior; untouched runtime remains the original41f binary.

The first patch script missed a formatted signature; its no-elision repeat/build was stopped before capture and retained as a rejected build attempt. Final assertions were rerun on both behaviors. No raw attempt was discarded.

Pinned authority: `PatchedDataComponentMap.set` compares against its prototype and removes an equal patch, while `asPatch` saves the remaining patch. Existing hive/map/tracker saved-only rules and PR9186 client stack handling were inspected and preserved. No pending production imported.
